Student Task Planner is a React Native mobile application built with Expo that helps students organize and keep track of their school assignments in one place. The app allows users to add new tasks by entering a title, subject, deadline in YYYY-MM-DD format, and an optional description, and it validates the deadline to ensure only real calendar dates are accepted. Tasks can be marked as complete or pending with a single tap on the checkbox, deleted with a confirmation prompt, and viewed through filters that let you show All, Pending, or Completed tasks, as well as filter by subject. Pending tasks that have passed their deadline are highlighted in red so overdue work is easy to spot, and the list is automatically sorted so pending tasks appear first, ordered by earliest deadline. Two summary cards at the top of the screen display the total number of pending and completed assignments, giving a quick snapshot of progress. All data is stored locally using SQLite through expo-sqlite, which means the app works completely offline and tasks persist between sessions without requiring any account or internet connection.

The project is organized into a small number of focused files. The main screen lives in App.js and is responsible for loading tasks from the database, holding the current filter and subject state, and rendering the list along with the form and filters. The database folder contains database.js, which opens the SQLite database, creates the tasks table if it does not exist, and exposes helper functions for initializing the database and performing create, read, update, and delete operations. The components folder holds taskform.js, a controlled form for entering new assignments that performs validation before submitting, and taskitem.js, which renders a single task card including its checkbox, title, subject, deadline, description, and delete button. The utils folder contains taskhelper.js, a collection of pure helper functions for sorting tasks, filtering them by status and subject, checking whether a task is overdue, and validating deadline strings. Keeping the business logic in pure helpers makes the rules easy to test and keeps the UI components simple.

To run the project, first make sure Node.js and the Expo CLI are installed, then run npm install to install dependencies. If you use the SafeAreaView from react-native-safe-area-context, install it with npx expo install react-native-safe-area-context and wrap your app root in a SafeAreaProvider. Start the development server with npx expo start, then press a for Android, i for iOS, or scan the QR code with the Expo Go app on your phone. Once the app is running, you can add your first assignment using the form at the top of the screen, tap the checkbox to mark tasks complete, use the filter buttons and subject chips to narrow down what you see, and delete tasks you no longer need by confirming the delete prompt.

A few design decisions are worth noting. The app is local-first, storing everything in SQLite so no network or authentication is required. Database queries use the array form of parameter binding, which is clearer and safer against future signature changes. All database access is centralized in database.js so UI components never touch SQL directly, and all business rules live in taskhelper.js as pure functions. Validation ensures that title, subject, and deadline are always provided, and the deadline must match YYYY-MM-DD and correspond to a real date, so entries like 2024-02-30 or 2024-13-01 are rejected while 2024-03-15 is accepted. One important detail to keep in mind is that the helper file is named taskhelper.js (lowercase, singular), and all imports must match this exactly, because case-sensitive file systems such as Linux and Android bundling will fail to resolve a mismatched path and crash the form the first time it tries to validate a deadline.

Potential future improvements include editing existing tasks, notification reminders for upcoming deadlines, additional sort options such as by subject or priority, priority levels, a search bar for filtering by title, dark mode support, and optional cloud sync for sharing tasks across devices. If you run into trouble, the most common issue is the module-not-found error caused by importing from taskHelpers instead of taskhelper, so double-check the import path if the form crashes on submit. If the app stays stuck on the loading screen, check the Metro logs for a database error from initDatabase. If tasks seem to disappear after reloading, make sure the SQLite database file is not being wiped by a development client cache clear. The idea is simple, it's an app to help students like me keep track of all our school assignments so we don't forget anything. You can add new tasks by typing the title, subject, deadline (in YYYY-MM-DD format), and a description if you want. When you add a deadline, the app checks if it's a real date so you can't put something like 2024-02-30 which doesn't exist. Once a task is done, you just tap the checkbox to mark it complete, and if you don't need it anymore, you can delete it and it will ask you first to make sure. There are also filters so you can see All tasks, only Pending ones, or only Completed ones, and you can filter by subject too. If a task is past its deadline and still not done, it shows up in red so you know it's overdue. The tasks are sorted automatically with pending ones first and the ones with the earliest deadline on top. At the top of the screen there are two small cards showing how many tasks are pending and how many are completed, so you can quickly see your progress. Everything is saved on your phone using SQLite, so the app works even without internet and your tasks are still there when you close and open it again.

The project is split into a few files so it's not too messy. The main file is App.js and it handles loading the tasks, showing the list, and keeping track of which filter is selected. Inside the database folder, database.js opens the SQLite database, creates the tasks table, and has functions for adding, reading, updating, and deleting tasks. In the components folder, taskform.js is the form where you type in a new assignment, and taskitem.js shows one single task on the screen with its checkbox, title, subject, deadline, and delete button. Then in the utils folder, taskhelper.js has all the helper functions like sorting the tasks, filtering them, checking if a task is overdue, and checking if the deadline is a valid date. I put the logic in separate helper functions so the code is easier to read and the UI files stay simple.

A few things I want to point out about how I built it. First, the app is local-first, meaning everything is stored in SQLite on your phone so you don't need any account or internet connection. Second, I used the array form when binding parameters to SQLite queries because it's clearer and safer. Third, all database stuff is kept inside database.js so the UI components never touch SQL directly, and all the business logic is in taskhelper.js as pure functions. The validation makes sure title, subject, and deadline are always filled in, and the deadline has to match YYYY-MM-DD and be a real date, so 2024-02-30 or 2024-13-01 will be rejected, but 2024-03-15 is fine. One important thing to remember is that the helper file is named taskhelper.js with lowercase and no "s" at the end. I actually made a mistake before where I wrote taskHelpers instead of taskhelper in one of the imports, and the app crashed when I tried to add a task because the form couldn't find the file. So if you're on Linux or building for Android, make sure the import path matches the filename exactly because those systems are case-sensitive.
